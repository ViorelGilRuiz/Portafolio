PRODUCTO PROPIO / EN DESARROLLOAplicaciones & datos

I Do
Manager.

Del evento a sus documentos.
Sin perder el contexto.

Un proyecto para organizar la operativa de wedding planners: eventos, plantillas reutilizables y documentos vinculados a cada celebración.

  • Angular
  • NestJS
  • Prisma
  • SQLite · desarrollo
Consultar el repositorio (otra pestaña)
Leer el caso de estudio +

Contexto y objetivo

Evitar que la información de un evento quede dispersa. El proyecto vincula negocio, eventos, plantillas y documentos en un dominio común.

Mi contribución

Desarrollo del proyecto Full Stack: interfaz Angular, API NestJS y persistencia con Prisma en un monorepo.

Decisión de ingeniería

Separar la plantilla de su documento permite reutilizar estructuras sin mezclar contenidos. El servicio de eventos filtra por businessId y comprueba pertenencia antes de modificar datos.

Implementación comprobada

Creación, consulta, edición y eliminación de eventos; modelos de negocio y documentos. El esquema inspeccionado usa SQLite; el README también describe PostgreSQL con Docker.

Dificultad y aprendizaje

Un producto para varios negocios necesita asociar cada operación a su contexto. El dominio y los servicios hacen visible esa responsabilidad.

Estado y evidencia

En desarrollo. Revisión de código y documentación, sin validación comercial ni métricas de impacto. Colaboración en tiempo real y RBAC granular pendientes según el roadmap. Capturas reales pendientes de una sesión de prueba.

PROYECTO PERSONAL / PROTOTIPO LOCALFlujos & experiencia web

FitMenu
AI Studio.

Del perfil personal
a una semana organizada.

Exploración de una experiencia de planificación de menús. Este caso se centra en la versión HTML y JavaScript con persistencia local.

  • JavaScript
  • HTML / CSS
  • localStorage
Consultar el repositorio (otra pestaña)
Leer el caso de estudio +

Contexto y objetivo

Conectar un perfil con menús semanales y recetas en un recorrido navegable. Explorar la experiencia antes de depender de un backend.

Mi contribución

Desarrollo de la experiencia web y organización en servicios de sesión, almacenamiento, usuarios, recetas y menús.

Decisión de ingeniería

Separar servicios de datos y páginas permite revisar cada parte del flujo. El motor calcula una estimación calórica y rota recetas según dificultad y número de comidas.

Implementación comprobada

Generación de siete días, hidratación de recetas por identificador y guardado local. La sesión se simula en el navegador. El nombre AI Studio no implica que este motor utilice un modelo generativo.

Dificultad y aprendizaje

Mantener un estado coherente entre perfil, menú y receta requiere guardas de navegación y una capa común de persistencia.

Estado y evidencia

Prototipo sin autenticación de producción ni validación nutricional. El repositorio contiene una evolución Angular/NestJS fuera de este caso. Sin métricas de uso. Capturas reales pendientes.

04 / CÓMO TRABAJO

Primero entender.
Después construir.

La solución adecuada empieza por una buena pregunta.

  1. 01

    Entender

    Analizo contexto, requisitos y restricciones. Reproduzco el problema antes de intervenir.

  2. 02

    Diseñar

    Elijo una solución proporcionada. Valoro seguridad, mantenimiento y dependencias.

  3. 03

    Construir

    Implemento por partes, integro los componentes y documento las decisiones.

  4. 04

    Validar

    Pruebo el recorrido completo, reviso incidencias y preparo el mantenimiento.

El trabajo termina cuando se entiende cómo seguir cuidándolo.
